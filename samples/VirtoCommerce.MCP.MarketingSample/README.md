# MCP Marketing Sample

A marketer's toolset for an AI agent, built on `VirtoCommerce.MCP` and shaped as described in [Design a toolset](../../README.md#design-a-toolset). The agent sees and changes only what the marketer may see and change, anything that gives money away waits for a second person, and every call is audited.

The sample works on realistic mock data in memory, so it can be shown on any platform without touching real promotions: three stores, sixteen promotions, coupons, results and 30 days of orders, seeded relative to today and the real retail calendar. The next Black Friday is always ahead, a laptop sale is about to end, and a flash sale is over its budget.

> [!WARNING]
> The sample is for demos only. Do not install it on a shared or production environment.

## Overview

What the marketer gets:

| Ask | What happens |
| --- | --- |
| "How is marketing doing?" | One overview per store: live promotions, spend against the monthly budget, the best promotions of the week, what ends or starts soon, the top issues, the retail events ahead. |
| "Is anything wrong?" | A health check with a suggested action for each finding: a budget almost spent, a discount above policy, a strong promotion about to end, a weak one, a coupon promotion without coupons, missing translations. |
| "Do any promotions clash?" | Discounts that stack, an exclusive promotion hiding another, two exclusive ones with the same priority, redundant free shipping. |
| "Which promotions earn the most for the discount?" | A ranking by revenue per unit of discount, with a verdict for each promotion. |
| "Pause the headphones flash sale, it is over budget." | Paused at once: pausing limits risk, so it needs no approval. |
| "Extend the laptop sale by a week." | A preview with the estimated extra cost goes to an approver; the promotion changes when they approve it. |
| "Prepare Black Friday." | Drafts with names in every store language, a conflict check, coupon codes generated by a background job, then scheduling for approval. |
| "Clean up old coupons." | Coupons of ended promotions are deactivated by a background job. |
| "A customer says WELCOME10 did not work on order CO-10482." | The reason in one answer: the code is for first orders, and the customer has ordered before. |
| "What would 15% off monitors cost us?" | A simulation on the last 30 days of orders: hit rate, average discount, total exposure. |
| "Do the same Black Friday setup for the Fashion store, a week later." | A draft copy with shifted dates, and warnings for what does not fit the other store. |
| "What does the home page show next week, and what is empty?" | The placement map and the content gaps: the hero is empty after the autumn sale, the checkout upsell runs out, a loyalty card targets a deleted segment. |

The demo data: three stores (Electronics, B2B Office Supply, Fashion Outlet), sixteen promotions, coupons, five customer segments, 30 days of orders, and the placeholders, banners and publications of each store. Each promotion is there to show one finding; the comments in [`Data/MarketingDemoSeed.cs`](Data/MarketingDemoSeed.cs) say which. Order `CO-10482` is a coupon complaint to explain.

## Features

The tools are in the `admin` scope and protected with the permissions of the Marketing module (`marketing:read`, `marketing:create`, `marketing:update`), which they respect when limited to stores; the content tools use the permissions of the Content module (`content:read`, `content:create`, `content:update`).

| Layer | Tool | What it does | Approval |
| --- | --- | --- | --- |
| Orientation | `get_marketing_overview` | Per store: live, scheduled, draft and paused promotions, spend against the monthly budget, best promotions of the week, what ends or starts soon, top issues, retail events ahead | |
| Orientation | `get_promotion_calendar` | The plan against the retail calendar, with events no promotion covers | |
| Orientation | `describe_promotion_rules` | What a promotion can say: rewards, targets, conditions, how promotions combine | |
| Finder | `search_promotions`, `get_promotion` | Compact rows; one promotion with a plain-language explanation, results, policy warnings and conflicts | |
| Finder | `search_coupons`, `list_customer_segments` | Codes with their use; segments with their size | |
| Analysis | `analyze_promotion_performance` | Revenue per unit of discount, order value uplift, budget used, trend, verdict | |
| Analysis | `find_promotion_issues` | Health check: budget almost spent, above the policy limit, ending while strong, underperforming, no coupons, stale coupons, missing translations | |
| Analysis | `find_promotion_conflicts` | Stacking, shadowing by an exclusive promotion, equal priorities, redundant free shipping; for all promotions or one | |
| Analysis | `simulate_promotion` | A promotion, even a draft, against the last 30 days of orders: hit rate, average discount, exposure, why orders miss it | |
| Analysis | `explain_promotion_evaluation` | Why an order got or did not get each promotion ("my code did not work") | |
| Analysis | `get_coupon_usage` | Unused, used, used-up and deactivated codes, redemptions by day, rejected attempts | |
| Action | `create_promotion_draft`, `update_promotion_draft`, `clone_promotion` | Drafts are invisible to customers | no |
| Action | `set_promotion_translation`, `pause_promotion` | A missing name; stop a promotion at once (`pause_promotion` asks the user to confirm in the chat) | no |
| Action | `schedule_promotion`, `activate_promotion` | Go live; the preview includes conflicts and a simulation | yes |
| Action | `extend_promotion`, `change_promotion_discount` | The preview estimates the extra cost or shows the policy check | yes |
| Bulk | `generate_coupons` | Codes created by a background job; the preview shows the first codes | above 1,000 codes |
| Bulk | `deactivate_stale_coupons` | Codes of ended promotions, deactivated by a background job | no |
| Content: orientation | `get_placement_map` | Every placeholder of a store on a date: what is shown, for whom, what comes next, empty slots | |
| Content: finder | `list_content_placeholders`, `search_content_items` | Placeholders by page; banners, HTML blocks and carousels with where they are published | |
| Content: analysis | `find_content_gaps` | Empty slots, publications without a successor, audiences that can never match, banners of promotions that are not live | |
| Content: analysis | `explain_content_resolution` | Which publication a customer of a segment sees on a date, and why the others are not shown | |
| Content: action | `create_content_item`, `unpublish_content` | A new item; take a publication down at once | no |
| Content: action | `publish_content`, `reschedule_publication` | Scheduling for later applies at once; a window that includes today needs approval | when live today |
| Content: action | `propose_content_copy` | New text for a banner, written by the agent from a brief; the old and new text side by side for the approver | yes |
| Content: bulk | `clone_content_campaign` | Copy publications to another store, shifted in time, by a background job | no |

Every action takes `dryRun` and returns an `McpChangePreview`: the changed fields and warnings for the approver.

The MCP module adds its own tools to the same scope: `list_pending_changes`, `get_pending_change`, `approve_pending_change` and `reject_pending_change` for approvals, `get_job_status` and `cancel_job` for background jobs.

Prompts: `weekly_marketing_review`, `plan_campaign`, `promotion_post_mortem`. Resources: `marketing://policies/discounts`, `marketing://playbooks/sale-event`, `marketing://calendar/retail-events`.

## Setup

You need a platform with `VirtoCommerce.MCP`, `VirtoCommerce.Marketing` and `VirtoCommerce.Content` (and `VirtoCommerce.BackgroundJobs` for the bulk tools), and an MCP client that supports OAuth: Claude Code, Claude Desktop, or any other. The examples use `http://localhost:10645` as the platform URL; replace it with yours.

1. **Install the sample.** Build this project and copy `module.manifest` and the `VirtoCommerce.MCP.MarketingSample.*` files from `bin/Debug/net10.0` into `modules/VirtoCommerce.MCP.MarketingSample/bin` of the platform (the manifest one level up, next to `bin`).

1. **Allow tokens for the MCP endpoint** in the platform `appsettings.json`, with your platform address:

    ```json
    "Authorization": {
      "Resources": [ "http://localhost:10645/admin/mcp" ]
    }
    ```

1. **Register the MCP client** once, as an administrator, in **Security → OAuth applications** (Admin Shell or classic Manager): **Add**, Display name `Marketing agent`, Client ID `mcp-demo`, Client type *Public* (PKCE switches on), Consent *Explicit*, Grant types *Authorization code* and *Refresh token*, Redirect URI `http://localhost:65111/callback`, and under **Resources** tick *MCP: Virto Commerce Back Office* (`http://localhost:10645/admin/mcp`). [Set up the platform for agents](../../README.md#set-up-the-platform-for-agents) shows the screen.

1. **Create the roles** in **Security → Roles**:

    | Role | Permissions | Who |
    | --- | --- | --- |
    | `mcp-marketer` | `marketing:access`, `marketing:read`, `marketing:create`, `marketing:update`, `content:access`, `content:read`, `content:create`, `content:update` | Marketers |
    | `mcp-approver` | `mcp:approve`, `mcp:audit:read`, `marketing:access`, `marketing:read`, `marketing:update`, `content:access`, `content:read`, `content:update` | The marketing lead who approves changes |
    | `mcp-marketer-fashion` | as `mcp-marketer`, with `marketing:read` limited to the **Fashion** store | A marketer of one store |

    Save a role with store-limited permissions twice: the platform keeps permission scopes only when a role is updated.

1. **Create users** with these roles, for example `mcp-marketer`, `mcp-approver` and `mcp-marketer-fashion`.

1. **Connect the agent.** For Claude Code, in an empty folder:

    ```bash
    claude mcp add --scope project --transport http --client-id mcp-demo --callback-port 65111 virto-marketing http://localhost:10645/admin/mcp
    ```

    Start `claude`, run `/mcp`, choose `virto-marketing` and **Authenticate**. The platform sign-in page opens; sign in as the marketer. The approver does the same in a second folder, after signing out of the platform in the browser. Other agents are in [Connect an AI agent](../../README.md#connect-an-ai-agent).

## Scenarios: a week with the agent

### Monday: the weekly review

Run the prompt `/weekly_marketing_review` (MCP clients show the server's prompts as commands), or ask "How did marketing do last week, and what needs my attention?".

The agent calls `get_marketing_overview`, `find_promotion_issues`, `find_promotion_conflicts` and `analyze_promotion_performance`, then writes the review: the spend against the budget, the best promotions of the week, and at most five actions, the most urgent first. In the demo data it finds, among others:

- The headphones flash sale is at 30% off, above the 25% policy limit, and 87% of its budget is spent.
- The autumn laptop sale is the best promotion of the week and ends in two days.
- The Cyber Monday promotion needs a code, but has no coupons.
- Black Friday has no French name, the boots promotion no English one.
- The monitor bundle has run for 25 days with almost no redemptions.
- 120 codes of the back-to-school promotion still work, although it ended in September.

The review changes nothing. The marketer decides what to do.

### Monday, 9:30: stop the bleeding

> Pause the headphones flash sale, it is over the policy limit.

`pause_promotion` runs at once and returns the diff (`status: active → paused`). Pausing limits risk, so it needs no approval. The agent may run it with `dryRun` first to show what will change.

### Monday, 10:00: extend a winner

> The laptop sale is doing great. Extend it until next Sunday.

`extend_promotion` does not change the promotion. It submits a change for approval, with a preview the approver will see:

```json
{
  "action": "extend",
  "object_id": "autumn-laptops",
  "changes": [ { "field": "end", "from": "2026-10-31", "to": "2026-11-08" } ],
  "warnings": [
    "Estimated extra discount cost: about 30,011 USD for 8 more days, at the pace of the last 7 days.",
    "Conflict (stacking) with 'Welcome offer: 10% off the first order' (welcome-10): ..."
  ]
}
```

The agent tells the marketer the change id. The marketer cannot approve it: they do not have the `approve_pending_change` tool.

### Monday, 10:15: the approver's inbox

The marketing lead asks their own agent:

> What is waiting for my approval?

`list_pending_changes`, then `get_pending_change` show each change with its arguments and preview. "Approve the laptop extension" runs `approve_pending_change`: the agent's client asks the approver to confirm in the chat, then the promotion changes once, as the approver, and the result is recorded. A client that cannot ask refuses the call (audited `Declined`); the approver then approves in **Configuration → AI agents (MCP) → Agent approvals**. A change that breaks the policy, such as raising a discount to 40%, shows the policy warning in its preview; the lead rejects it with a reason with `reject_pending_change`, and the requester sees the reason.

### Tuesday: plan Black Friday

Run `/plan_campaign` with the goal "Black Friday" and the store `Electronics`. The agent reads the discount policy and the sale event playbook (resources `marketing://policies/discounts` and `marketing://playbooks/sale-event`), checks the calendar and what exists, compares past results, and proposes promotions. When the marketer agrees:

1. `create_promotion_draft` creates each promotion as a draft, with a customer-facing name in every store language.
2. `set_promotion_translation` adds the missing French name of the existing Black Friday promotion.
3. `find_promotion_conflicts` checks that nothing stacks above the policy.
4. `generate_coupons` prepares 2,000 single-use codes for Cyber Monday. More than 1,000 codes need approval; the preview shows the first ten codes, and after approval a background job creates them. The marketer follows it with `get_job_status`: `Running, 500 of 2,000`, then `Succeeded`, and could stop it with `cancel_job`.
5. The banner: `create_content_item` for the Black Friday hero text, then `publish_content` for the `home-hero` placeholder with the same dates. Scheduling for a later day applies at once; `explain_content_resolution` shows what a customer will see that day.
6. `schedule_promotion` submits each draft for approval with its dates.

### Wednesday: a coupon complaint

Support forwards: "Code WELCOME10 did not apply on order CO-10482."

> Why didn't WELCOME10 work on order CO-10482?

`explain_promotion_evaluation` lists every promotion of the store for that order. The welcome offer is for new customers only, and the customer has ordered before; the flash sale and free shipping did apply. `get_coupon_usage` shows the code itself works (thousands of redemptions) and how many orders tried it without qualifying. The marketer gets the root cause and a remedy in one exchange: a one-off code with `generate_coupons` and `count: 1`, which needs no approval.

### Thursday: test an idea, then copy a campaign

> What would 15% off monitors for two weeks cost us?

The agent creates a draft with `create_promotion_draft` and runs `simulate_promotion` on it: the share of last month's orders that would qualify, the average discount, and the total exposure. Nothing goes live; the draft stays as the record of the analysis.

> Do the same Black Friday setup for the Fashion store, a week later.

`clone_promotion` creates a draft copy in the Fashion store with the dates moved by seven days. Its preview warns that Fashion sells none of the copied categories, so the agent asks which categories to use and changes them with `update_promotion_draft`. A live or scheduled promotion is never edited in place: the tool asks to pause it first.

When the marketer asks to activate or schedule a promotion, the approver's preview includes the conflicts and a simulation of the discount per month.

### Thursday afternoon: the storefront content

> What does the home page show next week, and what is empty?

`get_placement_map` lists every placeholder of the store with what is shown, for whom and what comes next. `find_content_gaps` finds what needs work: the home hero is empty from the end of the autumn sale until Black Friday, the checkout upsell runs out next week, and the loyalty card on the account dashboard targets a segment that was deleted, so nobody sees it. `explain_content_resolution` with the segment `vip` proves it.

The agent can also write the banner text: "Write a German headline for the Black Friday hero, punchy, under 60 characters" ends in `propose_content_copy`, which holds the text for approval with the old and the new text side by side. The marketer creates a Singles' Day banner with `create_content_item` and schedules it with `publish_content` for the empty days: a window that starts later applies at once. Extending the checkout upsell from today goes live immediately, so it is submitted for approval, with a preview that shows what it overlaps. `clone_content_campaign` copies the Black Friday banners to the Fashion store a week later, as a background job.

### Friday: clean up and learn

> Deactivate the coupons of promotions that have ended.

`deactivate_stale_coupons` with `dryRun` shows 120 codes of the back-to-school promotion; without it, a background job deactivates them.

> Write a post-mortem of the back-to-school promotion.

The prompt `/promotion_post_mortem` compares its results with the other promotions of the store and suggests what to do differently next time.

### A marketer of one store

Sign in as `mcp-marketer-fashion`. The same tools are there, but every answer covers the Fashion store only. Asking about the laptop sale returns "You do not manage the marketing of store 'Electronics'", and the call is audited as `Forbidden`.

### What the agent cannot do

- Approve its own changes. Approval needs `mcp:approve`, and by default a change cannot be approved by the user who requested it.
- See or change another store's promotions when the marketer's permission is limited to some stores.
- Use a tool an administrator switched off. Enter `generate_coupons` in **Settings → MCP → Tools → Disabled tools**: the tool disappears from the agent on the next request, without a restart.
- Act unnoticed. **Configuration → AI agents (MCP) → Agent audit log**, and `POST /api/mcp/audit/search`, list every call with the user, the tool, the arguments and the outcome (`Succeeded`, `PendingApproval`, `Forbidden`, `Disabled`, `Failed`).

## How to extend

Every company has rules of its own: a cost center for every large budget, margin floors, a brand that is never discounted. They are added by a module of your own, without changing the marketing toolset. The sample is written for that, as a real module should be:

- Models are created with `AbstractTypeFactory` (`DemoPromotion.Create`), so a derived type replaces them everywhere.
- Services are registered in DI, and the methods of `MarketingAnalytics` and `PromotionEvaluator` are `virtual`, so a module adds its own rules in a derived class.
- Tools take their services from DI and use them for every rule, so a replaced service changes every tool.

The [extension sample](../VirtoCommerce.MCP.MarketingExtensionSample/README.md) uses each of these to add Contoso's finance rules: the marketer's existing tools report the new findings, and two tools and a `/finance_readiness_check` prompt are added, with unit tests. See also [How to extend](../../README.md#how-to-extend).

## Reset the demo

The demo data lives in memory: restart the platform to start over. Pending changes, jobs and the audit are stored in the database and stay.

## Troubleshooting

| Symptom | Cause |
| --- | --- |
| The agent has no marketing tools | The sample is not loaded, or the user has no `marketing:read` |
| The store-limited marketer sees every store | The role was created with the scope in one call; save it again |
| `generate_coupons` fails with "Background jobs are not available" | The `VirtoCommerce.BackgroundJobs` module is not installed |
| The sign-in ends with an error about the resource | `Authorization:Resources` or the client's **Resources** do not match the MCP address exactly |
